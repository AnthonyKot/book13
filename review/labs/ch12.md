# ch12 — Interfaces Belong to Consumers

**Verified.** Reference solution (one-method `UserStore` next to the service; field and constructor parameter changed to it; `Greeting` and `RealDB` untouched) passes all 5 hidden tests in yaegi and, with the top-level test declarations appended to a scratch `main`, under `go vet` and `go run -race` with go1.22.2. Starter behaves as designed in both toolchains: the hidden tests fail to compile at `NewUserService(fake)` (gc: "cannot use fake (variable of type *goShiftMemoryStore) as RealDB value"; yaegi: "cannot use type *main.goShiftMemoryStore as type main.RealDB"), which the app maps to `contractFailureMessage`. Prediction confirmed with gc, including the "only in the same package" distractor: the same interface is satisfied by a `MemoryStore` from a second package with no declaration. Also confirmed: a value of a type whose method has a pointer receiver does not satisfy the interface ("method UserName has pointer receiver"); the hidden fake relies on this by being passed as a pointer.

**Changed.**
- Hints escalated. Old hint 1 was the full interface declaration; now 1 locates the two spots that name `RealDB`, 2 states the method-set rule and why the interface is one method, 3 gives the shape.
- Lesson gained a paragraph on the two method-set facts a Java or TypeScript reader trips on: pointer receivers belong to `*T`, and `var _ UserStore = RealDB{}` is the compile-time assertion (verified to build).
- `real implementation` FAIL message now says what to change ("do not special-case the store type inside the service") instead of "should preserve RealDB behavior".

**Unsettled.** Nothing.
